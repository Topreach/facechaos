# Sound Grand Prix - sound acceleration correction, 0.14.2

Found a configuration defect: Sound Grand Prix inherited the shared optional microphone preference, whose default is false. It could therefore enter touch acceleration mode despite being presented as a sound racing game. It now uses its own grand_prix_microphone preference, default true. An explicit touch choice is still remembered; other games cannot overwrite the race preference. Voice Runner keeps its separate preference, and optional sound games keep their existing shared preference. Every game/stage entry reloads the correct sound preference rather than inheriting stale activity state.

The race already connected SoundGate strength to MiniGame and the race engine. This mapping is now shared by simulation and the visible power readout, so MIC ON / power percent / km/h reflects the actual throttle. Quiet removes throttle; the car coasts toward its base rolling speed. Sound strength is clamped and invalid strengths produce zero throttle. The instruction meter shows race power rather than an unrelated input level. Game geometry and camera quality are unchanged.

Missing microphone permission pauses Sound Grand Prix with permission/touch choices. Microphone start/read failure pauses the race and offers Retry voice, Use touch or Stay paused, rather than silently changing to touch mode. Stay quiet for the initial one-second noise calibration, then use a comfortable hum or aaa; stronger sound adds more acceleration. No shouting is needed. Explicit permission denial can still select touch mode, visibly labelled TOUCH MODE.

Verification: synthetic PCM samples passed through SoundGate, MiniGame.voiceSignal and RacingGame in all five stages. Tests confirmed calibration freeze, soft acceleration, stronger acceleration, quiet coasting, touch isolation and five complete PCM-driven race wins. Existing racing checks covered analog speeds, CPU wins/losses, checkpoint coins, microphone readiness and 100 head-dodge seeds/stages. Existing sound gate checks passed. Native checks used separate temporary preferences to verify defaults, independent settings and explicit touch persistence. Four native calibration/power/touch scenes rendered without microphone capture; the power scene was visually reviewed. Build and Android lint passed. Real voice/microphone performance still needs the user's live test. Installed versionCode 34 / 0.14.2-race on Samsung SM-A176B; test package removed.
